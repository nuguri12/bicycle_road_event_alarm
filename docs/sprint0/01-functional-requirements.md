# Functional Requirements Specification

## 1. 서비스 목표

주말 라이딩 전에 서울 및 경기도의 자전거 통행 방해 가능 이벤트를 짧고 이해하기 쉬운 Telegram Channel 메시지로 자동 발행합니다.

핵심 가치는 다음 한 문장입니다.

> 출발 전에 피해야 할 구간을 15초 안에 알려준다.

## 2. 대상 사용자

- 서울 및 경기도에서 주말 라이딩을 하는 소규모 자전거 그룹
- 예상 규모: 10명에서 100명
- 개인화 경로 안내가 아니라 공통 주의 구간 안내를 원하는 사용자

## 3. MVP 기능 범위

### 3.1 이벤트 수집

- 공공 웹페이지, 지자체 공지, 행사 안내 페이지에서 이벤트 정보를 수집합니다.
- 대상 이벤트 유형은 달리기 대회, 걷기 행사, 축제, 공공 행사, 도로 통제, 자전거 행사, 한강 및 하천 공원 행사입니다.
- 수집 대상 지역은 서울특별시와 경기도입니다.
- JavaScript 렌더링이 필요한 페이지는 Playwright 사용 여부를 Sprint 3에서 판단합니다.

### 3.2 이벤트 정규화

- 수집된 원문에서 제목, 날짜, 시간, 장소, 지역, 원문 URL, 영향도를 구조화합니다.
- 동일하거나 유사한 이벤트는 중복 후보로 식별합니다.
- 자전거 이용자 관점에서 주의가 필요한지 분류합니다.

### 3.3 이벤트 저장

- 정규화된 이벤트를 Supabase PostgreSQL에 저장합니다.
- 원문 데이터와 정규화 데이터를 분리하여 추적 가능성을 유지합니다.
- 중복 방지와 재처리를 위한 식별자를 저장합니다.

### 3.4 AI 요약

- OpenAI API는 자전거 이용자 관점 요약, 영향도 추정, 중복 판단 보조처럼 추론이 필요한 작업에만 사용합니다.
- 날짜, URL, 지역 필터링처럼 결정적인 작업에는 일반 알고리즘을 사용합니다.
- 생성 메시지는 15초 안에 읽을 수 있는 길이를 목표로 합니다.

### 3.5 Telegram 알림

- Telegram Bot API를 사용해 지정된 Telegram Channel에 주말 알림을 발행합니다.
- 메시지는 피해야 할 지역, 시간대, 이유, 원문 링크를 포함합니다.
- 발행 실패 시 재시도하고 실패 내역을 로그로 남깁니다.

### 3.6 스케줄러

- GitHub Actions로 정해진 시간에 자동 실행합니다.
- 기본 실행 주기는 주말 전 알림에 맞춥니다.
- 실패 시 다음 실행에서 재처리할 수 있어야 합니다.

### 3.7 로깅 및 모니터링

- 수집, 정규화, AI 생성, Telegram 발행 단계별 성공과 실패를 구조화 로그로 남깁니다.
- 장애 원인을 추적할 수 있도록 외부 API 응답 상태, URL, 실행 단계, 예외 유형을 기록합니다.

## 4. 제외 범위

- 모바일 앱
- 웹 프론트엔드
- 인증
- 사용자 계정
- 개인화 경로
- 관리자 대시보드
- 결제
- 분석 기능

## 5. 사용자 입력 필요 항목

- `[사용자 입력 필요]` Telegram Channel ID 또는 채널 사용자명
- `[사용자 입력 필요]` Telegram Bot Token 발급 여부
- `[사용자 입력 필요]` Supabase 프로젝트 URL 및 데이터베이스 연결 방식
- `[사용자 입력 필요]` OpenAI API Key 사용 가능 여부
- `[사용자 입력 필요]` 우선 수집할 공공 정보 출처 목록
- `[사용자 입력 필요]` 알림 발행 요일과 시간
- `[사용자 입력 필요]` 메시지 톤: 매우 간결한 경고형, 친근한 안내형, 중립 보고형 중 선택

## 6. 성공 기준

- 주말 전 자동 실행이 가능해야 합니다.
- 최소 1개 이상의 실제 공공 출처에서 이벤트를 수집할 수 있어야 합니다.
- 중복 이벤트가 Telegram 메시지에 반복 표시되지 않아야 합니다.
- 최종 메시지는 사용자가 15초 이내에 핵심 위험 구간을 파악할 수 있어야 합니다.
