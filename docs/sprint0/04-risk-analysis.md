# Risk Analysis

## 1. 공공 웹페이지 구조 변경

위험:

- 크롤링 대상 페이지의 HTML 구조가 변경되면 이벤트 수집이 실패할 수 있습니다.

완화:

- 출처별 크롤러를 분리합니다.
- 선택자 실패를 구조화 로그로 남깁니다.
- 원문 URL과 응답 상태를 기록합니다.
- 테스트 fixture를 두어 변경 영향을 빠르게 확인합니다.

## 2. 이벤트 정보 불완전성

위험:

- 날짜, 시간, 장소가 명확하지 않은 공지가 발행 대상에 포함될 수 있습니다.

완화:

- 필수 필드 검증을 적용합니다.
- 불완전한 이벤트는 발행 제외 또는 검토 필요 상태로 저장합니다.
- AI가 확실하지 않은 정보를 단정하지 않도록 프롬프트에 제한을 둡니다.

## 3. 중복 이벤트 발행

위험:

- 같은 행사가 여러 출처에 올라오거나 같은 출처에서 반복 노출될 수 있습니다.

완화:

- URL, 제목, 날짜, 장소를 조합한 결정적 중복 키를 사용합니다.
- 애매한 경우에만 AI 기반 중복 판단을 보조로 사용합니다.
- 발행 이력을 저장하여 같은 이벤트가 반복 발행되지 않게 합니다.

## 4. AI 요약 오류

위험:

- AI가 장소, 날짜, 영향도를 잘못 요약할 수 있습니다.

완화:

- 원문에서 추출된 구조화 필드를 우선 사용합니다.
- AI는 문장 생성과 영향도 설명에 집중합니다.
- 원문 링크를 포함해 사용자가 확인할 수 있게 합니다.
- 요약 실패 시 구조화 데이터 기반 fallback 메시지를 발행합니다.

## 5. Telegram 발행 실패

위험:

- Bot Token 오류, Channel 권한 오류, Telegram API 장애로 메시지가 발행되지 않을 수 있습니다.

완화:

- 발행 전 Bot 권한을 검증합니다.
- 재시도 정책을 둡니다.
- 실패한 메시지는 로그와 데이터베이스 상태로 추적합니다.

## 6. GitHub Actions 스케줄 지연 또는 실패

위험:

- GitHub Actions 스케줄은 정확한 실행 시간을 보장하지 않습니다.

완화:

- 알림 발행 시간을 여유 있게 설정합니다.
- 수동 실행 workflow를 제공합니다.
- 실행 실패 시 다음 실행에서 미발행 이벤트를 재처리합니다.

## 7. 비용 증가

위험:

- 이벤트 수가 많거나 재시도가 많으면 AI 비용이 증가할 수 있습니다.

완화:

- AI 호출 전 결정적 필터링과 중복 제거를 수행합니다.
- 이미 처리한 이벤트의 AI 결과를 재사용합니다.
- 월간 비용 상한을 운영 기준으로 둡니다.

## 8. 사용자 입력 필요 항목

- `[사용자 입력 필요]` 우선순위가 높은 리스크
- `[사용자 입력 필요]` 허용 가능한 알림 누락 수준
- `[사용자 입력 필요]` 운영자가 수동으로 개입 가능한 시간대
- `[사용자 입력 필요]` 비용 초과 시 동작 방식
