# Retry Policy

## 1. 재시도 목표

Telegram 발행 재시도는 일시적인 API 실패를 완화하되 중복 발행 위험을 만들지 않는 것을 목표로 합니다.

## 2. 재시도 대상

재시도하는 오류:

- 네트워크 timeout
- HTTP 429
- HTTP 500, 502, 503, 504

재시도하지 않는 오류:

- Bot Token 누락
- 잘못된 Channel ID
- Bot 권한 없음
- 메시지가 비어 있음
- 메시지 길이 초과
- HTTP 400, 401, 403, 404

## 3. 기본 재시도 설정

MVP 기본값:

- 최대 재시도 횟수: 2회
- 첫 재시도 대기: 2초
- 두 번째 재시도 대기: 5초
- 요청 timeout: 10초

HTTP 429:

- Telegram 응답에 retry_after가 있으면 해당 값을 우선합니다.
- retry_after가 없으면 10초 대기 후 1회만 재시도합니다.

## 4. 중복 방지 조건

재시도 전 확인:

- 같은 message_hash가 이미 success 상태로 기록되어 있으면 재시도하지 않습니다.
- sendMessage 응답이 성공으로 확인된 뒤에만 success를 저장합니다.

주의:

- timeout 직후 실제로 Telegram에 메시지가 게시되었을 가능성이 있습니다.
- 이 경우 다음 Sprint에서 운영 확인 절차를 문서화합니다.

## 5. 사용자 입력 필요 항목

- `[사용자 입력 필요]` Telegram 발행 최대 재시도 2회 승인 여부
- `[사용자 입력 필요]` HTTP 429 retry_after 우선 정책 승인 여부
- `[사용자 입력 필요]` timeout 후 중복 게시 가능성을 운영자가 수동 확인할지 여부
