# Coding Standards

## 1. 기본 원칙

- 단순하고 명시적인 코드를 작성합니다.
- 각 함수는 하나의 책임을 갖습니다.
- 숨겨진 전역 상태를 만들지 않습니다.
- 외부 API 호출은 모듈 경계 안에 격리합니다.
- 결정적 처리는 AI에 위임하지 않습니다.

## 2. Python 스타일

- Python 3.12 이상을 사용합니다.
- 타입 힌트를 작성합니다.
- Pydantic 모델로 외부 입력과 설정값을 검증합니다.
- Black으로 포맷합니다.
- Ruff로 lint를 검사합니다.
- Mypy로 타입 검사를 수행합니다.

## 3. 주석 규칙

사용자 요청에 따라 기능별 코드 구간에는 한글 주석을 작성합니다.

주석 원칙:

- 코드가 무엇을 하는지 반복하지 않고, 왜 필요한지 설명합니다.
- 기능 블록의 목적을 짧게 표시합니다.
- 외부 API 호출, 재시도, fallback, 중복 방지처럼 운영상 중요한 구간에 우선 작성합니다.
- 모든 줄에 주석을 달지 않습니다.

예시:

```python
# 이벤트 후보를 표준 모델로 변환하기 전에 필수 필드를 먼저 검증합니다.
validated_candidate = validate_raw_candidate(candidate)
```

## 4. 오류 처리 규칙

- 외부 API 오류는 재시도 가능 오류와 즉시 실패 오류로 구분합니다.
- 예외를 삼키지 않습니다.
- 로그에는 실행 단계, URL, 이벤트 식별자, 예외 유형을 포함합니다.
- 비밀값은 로그에 포함하지 않습니다.

## 5. 테스트 규칙

- 결정적 로직은 단위 테스트로 검증합니다.
- 외부 API는 mock으로 검증합니다.
- 크롤러는 샘플 HTML fixture로 검증합니다.
- AI 결과는 고정 입력과 mock 응답으로 검증합니다.

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` 한글 주석의 상세도 선호
- `[사용자 입력 필요]` Mypy strict 모드 적용 여부
- `[사용자 입력 필요]` 테스트 커버리지 목표 수치
