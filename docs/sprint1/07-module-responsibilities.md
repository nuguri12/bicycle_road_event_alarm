# Module Responsibilities

## 1. scheduler

책임:

- 전체 실행 순서를 제어합니다.
- 단계별 결과를 다음 단계에 전달합니다.
- 실패 시 처리 가능한 fallback 흐름을 선택합니다.

하지 않는 일:

- HTML 파싱
- AI 프롬프트 직접 작성
- Telegram API 직접 호출

## 2. config

책임:

- 환경 변수와 비밀값을 로딩합니다.
- 필수 설정 누락을 실행 초기에 감지합니다.
- 실행 환경별 설정을 제공합니다.

하지 않는 일:

- 비밀값을 로그에 출력
- 외부 API 호출

## 3. crawler

책임:

- 승인된 출처에서 원문 이벤트 후보를 수집합니다.
- HTTP 상태, 원문 URL, 수집 시간을 함께 반환합니다.
- 출처별 파싱 규칙을 격리합니다.

하지 않는 일:

- 이벤트 영향도 판단
- 데이터베이스 저장
- Telegram 메시지 생성

## 4. normalizer

책임:

- 원문 이벤트 후보를 공통 이벤트 모델로 변환합니다.
- 날짜, 시간, 장소, 제목, 원문 URL을 정규화합니다.
- 필수 필드 누락을 검증합니다.

하지 않는 일:

- 외부 페이지 요청
- AI 호출
- Telegram 발행

## 5. classifier

책임:

- 이벤트 유형을 분류합니다.
- 자전거 통행 영향도를 추정합니다.
- 발행 후보 여부를 결정합니다.

하지 않는 일:

- 최종 메시지 문장 생성
- 데이터베이스 연결 관리

## 6. database

책임:

- 이벤트, 원문, 발행 이력, 실행 결과를 저장합니다.
- 중복 여부를 조회합니다.
- 트랜잭션 경계를 관리합니다.

하지 않는 일:

- HTML 파싱
- 메시지 문장 작성

## 7. generator

책임:

- 발행 대상 이벤트를 Telegram 메시지로 변환합니다.
- 필요한 경우 OpenAI API를 사용합니다.
- AI 실패 시 fallback 메시지를 생성합니다.

하지 않는 일:

- 이벤트 수집
- 데이터베이스 스키마 변경

## 8. messenger

책임:

- Telegram Bot API로 메시지를 발행합니다.
- 발행 실패를 재시도 정책에 따라 처리합니다.
- 발행 결과를 반환합니다.

하지 않는 일:

- 이벤트 필터링
- AI 요약

## 9. logging

책임:

- 구조화 로그 형식을 제공합니다.
- 실행 ID와 단계 정보를 로그에 포함합니다.

하지 않는 일:

- 비밀값 기록
- 비즈니스 로직 수행

## 10. 사용자 입력 필요 항목

- `[사용자 입력 필요]` Classifier의 영향도 등급 체계 승인 여부
- `[사용자 입력 필요]` Generator가 빈 이벤트 목록일 때 메시지를 보낼지 여부
