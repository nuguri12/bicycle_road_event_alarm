# Token Optimization Strategy

## 1. 토큰 최적화 목표

AI 비용과 응답 시간을 줄이기 위해 프롬프트와 입력 데이터를 최소화합니다.

## 2. 입력 최소화

AI에 전달하는 데이터:

- 발행 대상 이벤트만 전달합니다.
- 원문 전체 본문을 전달하지 않습니다.
- 날짜, 장소, 영향도는 정규화된 필드만 전달합니다.
- URL은 source_url만 전달합니다.

AI에 전달하지 않는 데이터:

- raw_body 전체
- raw HTML
- 중복 제거된 invalid 이벤트
- needs_review 이벤트
- 이미 발행된 이벤트

## 3. 이벤트 수 제한

기본 입력 제한:

- 최대 5개 이벤트

초과 시 선택 기준:

1. high 영향도
2. medium 영향도
3. low 영향도
4. 가까운 날짜
5. 서울/경기도 우선순위 설정

## 4. 캐시 전략

동일한 이벤트 묶음에 대해서는 message_hash를 사용해 재생성을 피합니다.

캐시 후보:

- normalized_event_id 목록
- cyclist_impact_level
- start_datetime
- location_name
- title

## 5. 재시도 전략

AI 생성은 기본적으로 재시도하지 않습니다.

이유:

- fallback이 존재합니다.
- 비용 증가를 막습니다.
- 배치 실행 시간을 예측 가능하게 유지합니다.

예외:

- 네트워크 일시 오류에 한해 1회 재시도를 검토할 수 있습니다.

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` AI 입력 이벤트 최대 5개 승인 여부
- `[사용자 입력 필요]` AI 실패 시 재시도 0회 정책 승인 여부
- `[사용자 입력 필요]` message_hash 기반 재생성 방지 정책 승인 여부
