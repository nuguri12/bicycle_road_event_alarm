# Backup Strategy

## 1. 백업 목표

이 서비스의 데이터는 재수집 가능한 공공 정보와 발행 이력이 중심입니다. 따라서 고가용성보다 복구 가능성과 운영 단순성을 우선합니다.

## 2. 백업 대상

백업 대상:

- `run_logs`
- `raw_events`
- `normalized_events`
- `publish_attempts`

백업 제외:

- API Key
- Telegram Bot Token
- OpenAI API Key
- Supabase 연결 문자열

비밀값은 GitHub Actions Secrets 또는 별도 비밀 관리 기능에서 관리합니다.

## 3. 백업 방식

MVP 기본 방식:

- Supabase의 기본 백업 기능을 우선 사용합니다.
- 운영자가 필요할 때 수동 export를 수행할 수 있도록 절차를 문서화합니다.

보조 방식:

- 중요한 운영 전환 전에는 PostgreSQL dump를 생성합니다.
- dump 파일은 저장소에 커밋하지 않습니다.

## 4. 복구 기준

복구가 필요한 상황:

- 잘못된 migration 적용
- 대량 중복 데이터 삽입
- 발행 이력 손상
- 운영자가 원문 추적을 해야 하는 데이터 손상

복구 우선순위:

1. 발행 이력
2. 정규화 이벤트
3. 원문 이벤트
4. 실행 로그

## 5. 검증 방식

- 백업 파일이 생성되었는지 확인합니다.
- 테스트 데이터베이스에 복구 가능한지 확인합니다.
- 복구 후 주요 조회가 가능한지 확인합니다.

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` Supabase 요금제와 기본 백업 제공 여부
- `[사용자 입력 필요]` 수동 백업 수행 주기
- `[사용자 입력 필요]` 백업 파일 보관 위치
- `[사용자 입력 필요]` 허용 가능한 데이터 손실 범위
