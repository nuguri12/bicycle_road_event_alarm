# Incident Response

## 1. 장애 대응 목표

장애 대응은 잘못된 메시지 발행, 중복 발행, 실행 실패, 비밀값 노출 같은 상황에서 피해를 줄이고 복구하는 절차입니다.

## 2. 장애 등급

### 2.1 High

예:

- 운영 Channel에 잘못된 메시지 발행
- Bot Token 노출
- 대량 중복 발행
- 운영 DB 손상

대응:

- schedule 즉시 비활성화
- 관련 Secret 회전
- 원인 로그 확보
- 필요 시 Channel에 정정 공지

### 2.2 Medium

예:

- Telegram 발행 실패
- OpenAI fallback 반복
- 일부 출처 크롤링 실패

대응:

- 실패 단계 확인
- 수동 재실행 여부 판단
- 회귀 테스트 후보로 기록

### 2.3 Low

예:

- 이벤트 0건
- 일부 로그 누락
- 메시지 문구 품질 저하

대응:

- 다음 운영 점검 때 확인
- 필요 시 개선 backlog에 추가

## 3. 장애 기록 항목

- 발생 시각
- 감지 경로
- 영향 범위
- run_id
- message_hash
- 원인
- 조치
- 재발 방지 테스트 여부

## 4. 사용자 입력 필요 항목

- `[사용자 입력 필요]` High 장애 대응 담당자
- `[사용자 입력 필요]` 정정 공지 발행 기준
- `[사용자 입력 필요]` 장애 기록 저장 위치
