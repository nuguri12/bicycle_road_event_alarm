# Retry Policy

## 1. 재시도 목표

재시도 정책은 일시적인 네트워크 실패를 줄이되, 외부 공공 사이트에 부담을 주지 않는 것을 목표로 합니다.

## 2. 재시도 대상

재시도하는 오류:

- 연결 timeout
- 일시적인 DNS 오류
- HTTP 429
- HTTP 500, 502, 503, 504

재시도하지 않는 오류:

- HTTP 400
- HTTP 401
- HTTP 403
- HTTP 404
- 필수 selector 실패
- 날짜나 장소 파싱 실패

## 3. 기본 재시도 설정

MVP 기본값:

- 최대 재시도 횟수: 2회
- 첫 재시도 대기: 2초
- 두 번째 재시도 대기: 5초
- 요청 timeout: 10초

## 4. 출처 단위 실패 처리

한 출처가 실패해도 다른 출처 처리는 계속합니다.

예:

- 서울경찰청 교통정보센터 timeout 발생
- 실패 로그 기록
- 서울시 공식 공지 수집 계속 진행
- 최종 실행 상태는 `partial_success`로 기록

## 5. 로그 필드

재시도 로그에는 다음 값을 포함합니다.

- run_id
- source_name
- source_url
- attempt_number
- error_type
- http_status
- elapsed_ms

비밀값은 로그에 포함하지 않습니다.

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` 최대 재시도 횟수 2회 승인 여부
- `[사용자 입력 필요]` 요청 timeout 10초 승인 여부
- `[사용자 입력 필요]` HTTP 429 발생 시 더 긴 backoff를 둘지 여부
