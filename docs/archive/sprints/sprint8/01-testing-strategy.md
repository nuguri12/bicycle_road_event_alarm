# Testing Strategy

## 1. 테스트 목표

테스트는 자동화 파이프라인이 잘못된 이벤트를 발행하거나 중복 메시지를 보내는 위험을 줄이기 위한 품질 장치입니다.

핵심 목표:

- 결정적 로직은 단위 테스트로 검증합니다.
- 외부 API는 mock으로 검증합니다.
- 크롤러는 fixture HTML로 검증합니다.
- 실제 외부 호출은 별도 marker로 수동 실행합니다.
- 실패 복구와 중복 방지를 테스트합니다.

## 2. 테스트 계층

- Unit: 함수와 서비스 단위
- Integration: 모듈 간 데이터 흐름
- Contract-like mock: 외부 API 요청/응답 형태
- Regression: 과거 실패 사례 재현
- Live manual: 실제 외부 사이트 또는 Telegram 발행 확인

## 3. 품질 게이트

구현 후 기본 검증:

- `pytest`
- `ruff`
- `black --check`
- `mypy`

CI에서는 외부 네트워크가 필요한 테스트를 기본 실행하지 않습니다.

## 4. 테스트 데이터 원칙

- 비밀값을 테스트 데이터에 포함하지 않습니다.
- fixture에는 필요한 DOM 조각만 저장합니다.
- 날짜 의존 테스트는 고정된 기준 시간을 사용합니다.
- API 응답 mock은 실제 응답 구조를 참고하되 민감값을 제거합니다.

## 5. 사용자 입력 필요 항목

- `[사용자 입력 필요]` live 테스트를 CI에서 제외하는 정책 승인 여부
- `[사용자 입력 필요]` 기본 품질 게이트 4종 승인 여부
- `[사용자 입력 필요]` 날짜 기준 시간 고정 방식
