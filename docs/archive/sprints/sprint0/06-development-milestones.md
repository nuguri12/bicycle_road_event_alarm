# Development Milestones

## Milestone 0: Sprint 0 승인

목표:

- 구현 전 요구사항과 계획을 확정합니다.

완료 조건:

- Sprint 0 문서 7종이 작성됩니다.
- 사용자 입력 필요 항목이 검토됩니다.
- 승인 여부가 명시됩니다.

검증:

- 문서 파일 존재 확인
- `[사용자 입력 필요]` 항목 검토

## Milestone 1: 아키텍처 승인

목표:

- 모듈 경계, 데이터 흐름, 오류 처리 전략을 확정합니다.

완료 조건:

- Sprint 1 산출물이 승인됩니다.
- 구현할 폴더 구조와 책임이 확정됩니다.

검증:

- 컴포넌트 간 책임 중복 여부 검토
- 구현 범위가 MVP를 넘지 않는지 확인

## Milestone 2: 데이터베이스 설계 승인

목표:

- 이벤트 저장, 중복 방지, 발행 이력 추적을 위한 스키마를 확정합니다.

완료 조건:

- ERD, 엔티티, 인덱스, 마이그레이션 전략이 승인됩니다.

검증:

- 필수 조회 패턴을 지원하는지 검토
- 데이터 보관 정책 검토

## Milestone 3: 크롤러 구현 가능 상태

목표:

- 첫 번째 공공 출처를 안정적으로 수집할 수 있는 설계를 완료합니다.

완료 조건:

- 대상 출처와 테스트 계획이 승인됩니다.
- 실패와 재시도 정책이 확정됩니다.

검증:

- 샘플 HTML 기반 테스트 가능 여부 확인

## Milestone 4: 정규화 구현 가능 상태

목표:

- 수집 데이터를 공통 이벤트 모델로 변환하는 규칙을 확정합니다.

완료 조건:

- 필드 추출, 검증, 분류, 중복 규칙이 승인됩니다.

검증:

- 샘플 이벤트가 동일한 모델로 변환되는지 확인

## Milestone 5: AI 메시지 생성 가능 상태

목표:

- AI 사용 범위와 fallback 메시지 규칙을 확정합니다.

완료 조건:

- 프롬프트와 토큰 절감 전략이 승인됩니다.

검증:

- 샘플 이벤트에서 15초 이내 읽기 가능한 메시지 생성 가능 여부 확인

## Milestone 6: Telegram 발행 가능 상태

목표:

- Telegram Channel 발행과 실패 처리를 확정합니다.

완료 조건:

- Bot 권한, Channel 구조, 재시도 정책이 승인됩니다.

검증:

- 테스트 Channel 또는 실제 Channel 발행 방식 확인

## Milestone 7: 자동 실행 가능 상태

목표:

- GitHub Actions 기반 정기 실행을 확정합니다.

완료 조건:

- 스케줄, Secrets, 실패 복구 전략이 승인됩니다.

검증:

- 수동 실행과 정기 실행 시나리오 검토

## Milestone 8: 테스트 완료

목표:

- 핵심 기능의 회귀 검증 체계를 완성합니다.

완료 조건:

- 단위 테스트, 통합 테스트, mock 테스트 범위가 충족됩니다.

검증:

- Pytest, Ruff, Black, Mypy 실행

## Milestone 9: 배포 및 운영 준비 완료

목표:

- 운영자가 서비스를 배포하고 장애에 대응할 수 있게 합니다.

완료 조건:

- 배포 가이드, 운영 매뉴얼, 장애 대응 문서가 승인됩니다.

검증:

- 릴리즈 체크리스트 통과

## 사용자 입력 필요 항목

- `[사용자 입력 필요]` Milestone별 목표 일정
- `[사용자 입력 필요]` 테스트 Telegram Channel 사용 가능 여부
- `[사용자 입력 필요]` 첫 번째로 구현할 크롤링 출처
