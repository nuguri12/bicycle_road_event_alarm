# Maintenance Guide

## 1. 유지보수 목표

유지보수는 공공 웹페이지 변경, 비밀값 변경, 의존성 업데이트, 운영 정책 변경에 안정적으로 대응하기 위한 절차입니다.

## 2. 크롤러 유지보수

HTML 구조 변경 시:

1. 실패한 출처와 selector를 확인합니다.
2. 실제 페이지 또는 저장된 fixture를 비교합니다.
3. 실패 재현 테스트를 추가합니다.
4. 출처별 어댑터만 수정합니다.
5. 관련 크롤러 테스트를 실행합니다.

## 3. 비밀값 유지보수

Secret 회전 시:

1. 새 Secret을 발급합니다.
2. GitHub Actions Secrets를 업데이트합니다.
3. dry-run 또는 테스트 Channel 실행을 확인합니다.
4. 기존 Secret을 폐기합니다.

## 4. 의존성 유지보수

업데이트 원칙:

- 보안 업데이트를 우선합니다.
- 한 번에 많은 의존성을 올리지 않습니다.
- 업데이트 후 Pytest, Ruff, Black, Mypy를 실행합니다.

## 5. 데이터 유지보수

정기 확인:

- 중복 이벤트 증가 여부
- failed publish_attempt 누적 여부
- 오래된 raw_events 보관량
- run_logs 실패 패턴

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` 의존성 업데이트 주기
- `[사용자 입력 필요]` Secret 회전 주기
- `[사용자 입력 필요]` 크롤러 selector 점검 주기
