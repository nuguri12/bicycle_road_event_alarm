# Duplicate Rules

## 1. 중복 규칙 목표

정규화 단계의 중복 규칙은 여러 출처에서 같은 이벤트가 들어와도 최종 메시지에 반복 노출되지 않게 하는 것입니다.

## 2. deterministic_duplicate_key 구성

기본 구성:

- normalized_title_key
- start_date
- location_key
- region

생성 예:

```text
{normalized_title_key}|{start_date}|{location_key}|{region}
```

## 3. normalized_title_key

규칙:

- 공백을 제거하거나 하나로 통일합니다.
- 괄호 안 부가 설명은 제거 후보로 둡니다.
- `공지`, `안내`, `알림` 같은 일반 단어는 키에서 제외합니다.
- 숫자, 지명, 행사명은 유지합니다.

주의:

- 제목을 과도하게 줄이면 서로 다른 이벤트가 합쳐질 수 있습니다.

## 4. location_key

규칙:

- 대표 장소명을 사용합니다.
- `일대`, `주변`, `인근` 같은 접미사는 제거합니다.
- 교량, 공원, 하천 이름은 유지합니다.

## 5. 애매한 중복 처리

자동 병합하지 않는 경우:

- 같은 날짜와 지역이지만 제목이 완전히 다릅니다.
- 같은 축제의 여러 세부 프로그램입니다.
- 도로 통제 공지와 행사 공지가 같은 원인을 가리키지만 구간이 다릅니다.

처리:

- `validation_status`를 `needs_review`로 둘 수 있습니다.
- Sprint 5에서 AI 중복 판단 보조 대상으로 넘길 수 있습니다.

## 6. 사용자 입력 필요 항목

- `[사용자 입력 필요]` duplicate key에서 일반 단어 제외 목록 승인 여부
- `[사용자 입력 필요]` 같은 날짜와 장소의 다른 제목 이벤트를 자동 병합할지 여부
- `[사용자 입력 필요]` AI 중복 판단 보조로 넘길 후보 기준
