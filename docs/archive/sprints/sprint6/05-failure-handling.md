# Failure Handling

## 1. 실패 처리 목표

Telegram 발행 실패는 데이터 손실보다 운영자가 원인을 빠르게 확인할 수 있는 상태로 남기는 것이 중요합니다.

## 2. 실패 유형

### 2.1 설정 실패

예:

- TELEGRAM_BOT_TOKEN 누락
- TELEGRAM_CHANNEL_ID 누락

처리:

- 발행을 시도하지 않습니다.
- publish_attempts에 `failed` 또는 실행 로그에 설정 오류를 기록합니다.
- 비밀값 자체는 로그에 남기지 않습니다.

### 2.2 권한 실패

예:

- Bot이 Channel 관리자가 아닙니다.
- Bot에 게시 권한이 없습니다.

처리:

- 재시도하지 않습니다.
- failure_reason에 권한 오류 유형을 기록합니다.
- 운영자가 Channel 권한을 수정해야 합니다.

### 2.3 API 일시 실패

예:

- timeout
- HTTP 429
- HTTP 503

처리:

- 재시도 정책에 따라 제한적으로 재시도합니다.
- 최종 실패 시 failed로 기록합니다.

### 2.4 메시지 검증 실패

예:

- 메시지가 비어 있습니다.
- 메시지가 너무 깁니다.
- message_hash가 없습니다.

처리:

- Telegram API를 호출하지 않습니다.
- failed 또는 skipped로 기록합니다.
- 이전 단계의 메시지 생성 문제로 추적합니다.

## 3. 실패 후 재처리

다음 실행에서 재처리 가능한 경우:

- 이전 발행 시도가 failed입니다.
- 같은 message_hash의 success 기록이 없습니다.
- 현재 메시지 생성 결과가 동일하거나 안전하게 재생성되었습니다.

재처리하지 않는 경우:

- 이미 success 기록이 있습니다.
- 운영자가 수동으로 발행했지만 시스템에 기록하지 않은 경우입니다.

## 4. 사용자 입력 필요 항목

- `[사용자 입력 필요]` 설정 실패를 run_logs만 기록할지 publish_attempts에도 기록할지 여부
- `[사용자 입력 필요]` 운영자가 수동 발행한 메시지를 시스템에 기록할 방법 필요 여부
- `[사용자 입력 필요]` 최종 발행 실패 시 알림 받을 채널 또는 방식
